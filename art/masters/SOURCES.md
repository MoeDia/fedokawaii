# Master artworks for the pixel-art wallpapers and lock screens

What this is: the source list for turning old-master Japanese art into pixel art at 640x360. DARK theme = demons, ghosts, spectres, thunder and wind gods; LIGHT theme = Buddhist celestial beings (tennin, raigo, Kannon, Benzaiten, dragon-king scenes). 14 candidates each. The images themselves are not in the repo: they sit in `~/.cache/r27-art/<slug>.jpg` (28 files, 75 MB) and can be re-fetched from the "image URL downloaded" column; the sha256 column proves they are the files described here.

**Rule: only public-domain / CC0 open-access sources, each verified on its own record.** Every work here is also out of copyright by age (artists died 1716-1927 or are anonymous medieval); the museum record is the second, independent check. Checked 2026-10-27.

## How each source was verified

- **Met Open Access** (CC0): object record from `collectionapi.metmuseum.org/public/collection/v1/objects/{id}` has `isPublicDomain: true`; image = the record's `primaryImage` (original). The CC0 waiver and "images in the public domain" are stated in the API documentation https://metmuseum.github.io/ and the dataset README https://github.com/metmuseum/openaccess. Note: `/v1/search` was retired 2026-10-01; use `/v1.1/search` (offset/limit). The Met object pages answer scripts with HTTP 429, so the record was read through the API.
- **Art Institute of Chicago**: `api.artic.edu/api/v1/artworks/{id}` has `is_public_domain: true`; image = IIIF `full/{w},/0/default.jpg` with w = min(1686, native width) (the documented maximum for public-domain images; asking 1686 for a narrower image is redirected to 843, so the native width is requested). The IIIF server needs the documented `AIC-User-Agent` header; without it Cloudflare challenges the request. The AIC website pages (object page, open-access page) did not answer scripted fetches (timeouts, HTTP 403), so the "CC0" wording of the open-access page could not be read; the API's own `info.license_links` (CC0 1.0) and the `is_public_domain` flag are what is quoted.
- **Rijksmuseum**: Linked Art record on `id.rijksmuseum.nl` (via `data.rijksmuseum.nl/search/collection`); the visual item's `subject_to` right is the Public Domain Mark; the digital object is flagged downloadable; image = IIIF `full/max`.
- **Wikimedia Commons**: only files tagged `PD-Art` / `PD-old` / `PD-LACMA` / `Cc-zero` whose original is a museum work (museum named in the table; two temple-owned paintings are flagged, kichijoten and haya-raigo). The Commons file page is the licence statement; where the museum's own record was reachable it was read too (LACMA, Cleveland, Kyoto National Museum). Library of Congress was not used: loc.gov answers scripts with a Cloudflare challenge, and no LoC-sourced file was needed.
- Politeness: single-threaded, a descriptive User-Agent, 1.5-3 s between downloads. No bot challenge was circumvented.

Reading the "composition" column: percentages are of the downloaded file (x from the left, y from the top). "16:9 crop" says what a 16:9 window of the picture keeps or loses. `[tone]` is the ground colour, since the dark theme wants dark grounds and the light theme wants light ones.
