## 5. Upgrade path F44 -> F45

### 5.1 The official procedure (and what it says today)

Source: [Upgrading Fedora Linux Using DNF System Plugin](https://docs.fedoraproject.org/en-US/quick-docs/upgrading-fedora-offline/)
(page "Version F44", last review 2026-04-29 - **not yet updated for F45**; it still shows `--releasever=44`, and says "You can also use 45 to upgrade to a Branched release").

1. `sudo dnf upgrade --refresh` and reboot - "Do not skip this step": it brings the signing keys of the next release. Checked: F44's `fedora-gpg-keys` 44-2 already contains `RPM-GPG-KEY-fedora-45-primary`/`-x86_64`.
2. `sudo dnf system-upgrade download --releasever=45` (the command is embedded in DNF5). "System upgrade is only officially supported and tested over 2 releases at most." If dependencies are unsatisfied "the upgrade will refuse to continue until you run it again with an extra `--allowerasing`"; `--best` shows more detail; `--setopt=keepcache=1` keeps the download cache across manual steps; a new key import asks for the fingerprint check.
3. `sudo dnf offline reboot` (cancel: `sudo dnf offline clean`); it reboots at once into the upgrade environment and once more into F45.
4. Optional afterwards: `rpmconf -a` (`.rpmnew`/`.rpmsave`; "Some third-party packages drop edited configuration files in /etc/yum.repos.d/ and reverting these files to their original versions may disable updates for the software"; the doc warns that applying the new defaults with rpmconf can revert `/etc/ssh/sshd_config` to the package default, which allows password authentication - relevant to the keys-only sshd hardening), BIOS-only `grub2-install`, `remove-retired-packages` (45.1-1.fc45 exists), `dnf repoquery --duplicates`, `dnf remove --duplicates`, `dnf autoremove`, old kernels, `clean-rpm-gpg-pubkey`, dangling symlinks, rescue kernel.
5. Release notes first: [F45 release notes](https://docs.fedoraproject.org/en-US/fedora/f45/release-notes/) (published, nearly empty: section 0).

### 5.5 Dates that matter

F44 stays supported until about 2027-06-02 (changeable); F45 until 2027-12-08; F46 lands about 2027-04-20 (final target) - so F44 -> F46 would be a two-release jump (the documented maximum), and F45 is the safer middle step. Release-day rule of thumb from the sources: wait for `releases/45/` to appear on the mirrors and for mesa 26.2.6 to reach F45 stable before running the real `system-upgrade download`, then expect to answer `--allowerasing` for `protobuf-compiler` only.
