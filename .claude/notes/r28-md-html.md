# "Anthropic says .md files are dead, HTML is next" (r28 f18, 6 Nov 2026)

The page of Anthropic's documentation that governs these files says no such thing (only that page was read, not all their docs). The headline traces to a post by Thariq Shihipar, reported as a Claude Code engineer at Anthropic (x.com/trq212/status/2052809885763747935, covered by 11 May 2026; the post itself not read, X answered HTTP 402 to the fetch, so this rests on its companion page thariqs.github.io/html-effectiveness/ and on a newsletter's summary), and "dead" is the headlines' word. The companion page argues something narrower: for output a person reads, HTML shows what Markdown flattens ("Diffs and call-graphs are spatial information; markdown flattens them") and side-by-side options beat "three sequential walls of text". It does not mention CLAUDE.md, skills or instruction files. The official docs (code.claude.com/docs/en/memory, read today) still define "CLAUDE.md files are markdown files", say the same of rules and auto memory, ask for "markdown headers and bullets" and a target under 200 lines; the only HTML in them is that block-level HTML comments are stripped before Claude sees the file. Decision: CLAUDE.md (137 lines), the memory, the ledger, the plan and every note stay as they are, because Claude Code reads them that way and grep and tail work on them. Adopted: nothing today. The one case the argument fits, picking between designs by eye, is already served better here by the JPEG option sheets, and a page of its own would add a format with no reader while the owner is away. If a later review truly needs a diff or a call graph laid out in space, one throw-away HTML page is allowed for it, with the Markdown record kept as the source.
